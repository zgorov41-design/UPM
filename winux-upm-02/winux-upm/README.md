# Winux UPM 0.2

Безопасный прототип Winux Universal Package Manager.

## Что умеет эта версия

- Определяет DEB, SNAP и Windows EXE по содержимому, а не по расширению.
- Показывает базовую информацию о файле.
- Для DEB проверяет пакет через `dpkg-deb`, если утилита установлена.
- Для SNAP проверяет `meta/snap.yaml`, если доступен `unsquashfs`.
- Для EXE проверяет PE-заголовок и базовую целостность заголовков.
- Результат содержит статус `valid`, `candidate` или `invalid`.
- Не устанавливает, не запускает и не изменяет пакеты.

## Чего пока нет

- Установки и удаления пакетов.
- Интеграции с `snapd` и Wine.
- GUI, системной службы D-Bus/Polkit и базы SQLite.
- Проверки цифровых подписей и полноценного анализа безопасности.

Это намеренно: сначала строим надёжное распознавание, затем добавляем операции установки.

## Установка для разработки

```bash
cd winux-upm
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
```

## Использование

```bash
upm detect ./package.deb
upm detect ./application.snap
upm detect ./setup.exe
upm detect ./some-file --json
```

Можно передать файл с любым расширением: формат определяется по сигнатурам.

## Тесты

```bash
python -m unittest discover -s tests -v
```

## Архитектурный принцип

UPM — это оркестратор, а не замена системным менеджерам:
- DEB: в будущем вызывать `apt`/`dpkg`.
- SNAP: в будущем взаимодействовать с `snapd`.
- EXE: в будущем запускать через Wine в отдельном prefix.

Следующий этап после 0.1 — безопасный CLI для просмотра установленных приложений и проектирование API системной службы. Не запускать команды установки от root через произвольную строку shell.

## UPM 0.2

```bash
upm detect ./file
upm inspect ./file --json
upm validate ./file
```

`validate` ничего не устанавливает и не запускает. Для DEB используется `dpkg-deb`, для SNAP — только чтение SquashFS через `unsquashfs`, если он установлен.
